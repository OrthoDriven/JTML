### Q1. Seed pipeline — the widgets path never uses the controller seed at all

**Finding (corrects the prior report's framing; prior seam-5 called the seed machinery "PEEL"; with one client it is plain DELETE):**

- The widgets `setSeedPose` call count is **zero**. `setSeedPose|applySeedPose|seedApplied|seedRestored|hasSeedPose` have no production call sites; the only controller-seed API touched by widgets is `clearSeedPose()` (mainscreen.cpp:146). The services layer agrees: `ml_orchestrator.cpp:84-87` — *"widgets: the storage write above IS the seed; QML: OptimizerBridge::setSeedPose"*.
- **The shell snapshot/restore (M10a) is dead for widgets**: `start()`'s seed block (controller.cpp:104-122: `takeSeedForRun` :105, snapshot :108-112, restore on Initialize failure :176-181) can never execute its body — `has_seed_pose_` is never set to true in the widgets world, so `takeSeedForRun` (core impl controller_core.cpp:96-115) always returns `applied=false`. Deleting the entire block is behaviorally inert for widgets.
- **The stale guards (core controller_core.cpp:104-111) defend nothing on the widgets path** — they guard the QML pending-seed (prior comment cites "OptimizerBridge.cpp:276-291 preserved", controller_core.cpp:104).
- **`clearSeedPose` at mainscreen.cpp:146 is doubly dead.** The lambda is the `SessionStateController` `clear_seed` callback (mainscreen.cpp:134-146; session_state_controller.cpp:32-38), invoked only from `ResetForDatasetClear()` (session_state_controller.cpp:115-129) — and `ResetForDatasetClear` has **zero production callers**: its only caller is `StudyBridge.cpp:247` (experimental). So: constructor param + `clear_seed_` member + the call in `ResetForDatasetClear` + the mainscreen lambda all delete.
- **Answer to the simplification question: yes.** With the experiment deleted, the whole seed pipeline reduces to what widgets already does: *SavePose writes the estimate into `model_locations_` → `LaunchOptimizer` copies it → controller refreshes the payload → run*. Nothing else remains. **Keep from the seed region:** `storage_` member + terminal-frame `SavePose` in `onManagerOptimizedFrame` (controller.cpp:302-311) and the P1-2 payload refresh (controller.cpp:118-125) — both are load-bearing for the widgets mirror/estimate flow (the mirror at controller.cpp:63-74 writes `req.storage` *after* the hop-1 copy at :58, so the refresh is required even with the seed block gone).

### Q2. 8 binds + H1 epoch/sender guard + ghost quirk — still mutually defending, still widgets-reachable
